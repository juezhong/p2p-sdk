# 安全架构与威胁模型（草案 v0.3）

> 安全目标是要求，不代表已完成安全审计。

## 信任边界

- **P2P 通信端点**：必须验证对端身份后才能交换应用数据；所有业务数据须端到端加密。
- **手动邀请码/回传码**：是带时效和会话绑定信息的敏感连接凭据；不应被持久化在常规日志或诊断报告中。
- **可选信令服务器**：只允许投递具有明确 schema 的配对/候选/状态消息；不承载应用数据，不充当 TCP/UDP 转发器、TURN 或其他代理。
- **STUN 服务器**：可发现映射信息，但不提供业务数据中继。
- **持久设备身份**：后续可使用长期设备密钥和可信设备列表。密钥证明身份，不等于网络地址发现。

## 不可退让的安全要求

1. Peer 身份认证与加密传输绑定。ICE 的 `ufrag/password` 用于 ICE 检查认证，**不可**代替 QUIC/其他传输的对端身份认证。
2. TLS/QUIC 证书校验不得为“连通性方便”而跳过；手动配对可绑定一次性指纹，持久配对采用受信公钥/设备标识。具体密钥格式待设计。
3. 所有信令交换必须绑定 session ID / nonce / 过期时间并防重放；手动连接码须检查合法性、版本、长度、认证信息。
4. 信令服务器认证连接对方，限制请求速率、消息长度、会话寿命；客户端不得因为服务器提供候选地址就认为身份可信。
5. Direct-only 是强制运行策略：**禁用 TURN relay candidate，不接受 relay fallback，不能用可选服务器透明转发业务数据**。
6. 诊断默认脱敏：隐去密钥、token、ICE 密码及必要的用户隐私。导出公网/私网地址应有明确脱敏选项。
7. 可选的信令层端到端加密：业务传输加密是硬性条件；是否要求服务器无法读取候选 IP/端口，需要独立确定元数据隐私级别。服务器始终不得解密业务内容。
8. 界定资源限额：每 peer 的待验证候选数、握手并发、速率限制、超时、连接与流数量，防止未经授权的资源消耗。

## 失败时的安全行为

- 认证失败：立即拒绝会话，不降级到明文，也不自动信任新的密钥。
- 无直连路径：明确返回 `NoDirectPath`，不使用任何中继。
- 信令服务不可用：手动模式仍可使用；自动模式报告信令失败。
- 网络切换：必须重新验证路径与会话绑定，不能自动信任新的远端地址。
- 日志和错误报告：不输出完整邀请码、持久私钥或其他认证秘密。

## 待定事项

- 持久设备密钥算法、配对/撤销/轮换策略。
- 会话短期凭据编码及 Go 旧版兼容性。
- 信令元数据是否强制端到端加密。
- 安全审计、依赖许可证审计与模糊测试基线。


## 2026-10-10：QUIC 早到和运行期新端口的信任边界

未认证的 QUIC Initial、普通 STUN、来源 IP、LAN 子网相似性均不构成会话就绪或直连认证。JOIN 提前启动 listener 只使报文能够进入加密认证；成功须验证证书 PIN、Session HMAC、用户配对确认及创建方认证 Control 选择消息。动态 UDP 远端来源首先必须通过 HMAC、相反角色、时间窗口、nonce 防重放验证；新路径上再次使用 mTLS + Session HMAC，失败关闭连接。竞速上限仍然有限，未经确认的身份绝不进入业务会话。
