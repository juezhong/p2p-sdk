# SDK 网络/会话行为验收决策（2026-10-10）

> 用户已确认。**唯一对等标准是 Go p2p-friend v0.16.4 可观察网络功能与稳定性**，不是源码形状、线程模型、字段名或网络协议二进制格式。
> 本文件是实现要求，不代表对应行为已通过测试。当前 Rust 对照提交：SDK main `5aa615d`。

## 一、人工 INVITE/REPLY 与时钟（A1、A2、A12）

- 创建方生成 INVITE 后应当无限期等待人工转交 REPLY；用户可能 30 分钟、2 小时甚至更晚才输入。加入方产生 REPLY 后也不能立刻启动有限的 ICE/QUIC 失败计时器；需要响应式地等待经过认证的对端网络活动，或可验证的入站 QUIC。
- **用户显式取消、应用退出或者本地网络资源发生不可恢复错误**才结束人工等待。ICE/QUIC 真正开始后可以有有限、清晰的网络故障期限。
- 当前 SDK 的自动 INVITE 原先仅 1200 秒、底层手动配对上限 1800 秒，实际违反本决策。修复必须覆盖 `begin_creator_auto`、`begin_creator` 的可选有效期、`begin_joiner`、`receive_reply` 和等待阶段；不得为了无限等待关闭 HMAC/证书指纹校验。
- Go/Rust **不要求邀请码互通或共享序列化格式**；只保证各自端到端安全配对、错误码/角色校验与抗重放语义。

## 二、地址发现、LAN、STUN、网关（A5–A11、B4、B5）

- 两个完全不同的家庭网络也可能同时使用 `192.168.1.0/24`。**相同私网段不是 LAN 可达性的证据**，即使发送真实 CIDR 前缀也只能提高优先级，不能单凭 CIDR 判定已连通。
- 同一 LAN 上经过真实网络验证的 Host 路径应优先；可给予疑似 LAN 一个**短、有限的 head-start**，其他公网 IPv6、直接公网 IPv4、显式端口映射、srflx、prflx 仍必须保留并准时竞速。LAN Host 不通必须自动失败回退，不能独占整个超时。
- 具备全球单播 IPv6、两侧防火墙允许的情况下优先使用 IPv6 直接连接；存在 IPv6 防火墙时仍必须尝试反方向 Dial/Accept 及 IPv4/NAT 路径。**IPv6 地址存在不保证入站必然可达**。
- STUN 默认至少提供 Cloudflare + Google **独立提供商**，可配置/禁用。利用同一个实际 UDP socket 对多个服务器比较映射；保留多个响应和映射诊断。
- STUN、PCP/NAT-PMP/UPnP 同阶段并发。发现一个有效路径后**短暂等待其他能改善穿透的结果**，以软截止而非等待全部慢任务；全局硬截止保护上限。若后台映射任务后到，必须清理无用映射，不能泄露路由器规则。
- `prflx` 是认证 Punch/ICE 实际看到的公网/NAT 映射源地址。在真正完成安全 QUIC 之前，延迟出现的新地址也要能进入后续候选重试，减少 NAT 变化引起的连接失败。

## 三、QUIC、候选与连接方向（B3、B4–B8、C3）

- **两个独立竞速维度**：
  1. 候选/路径竞速：LAN、IPv6、公网 IPv4、端口映射与 NAT；首条 ICE 提名路径若 QUIC TLS/应用认证失败，应在整体预算内继续检查其他候选，不因一次失败提前结束。
  2. 主动/被动方向竞速：双方都可以监听、都可以主动拨号，实际能通的那一侧可获胜。方向仲裁要使双方引用**同一条实际 QUIC**，失败者可取消释放。
- 使用哪个具体算法不作规定，可利用 Rust ICE + Quinn + Tokio；但 Go 已实现的**功能层面候选优先、短超时、失败回退、双向直连**不得减少。
- 额外 QUIC 是通用 SDK 连接，不存在特殊「四路 Data」稳定机制。附属连接的实际拨号方必须服从已成功 Control QUIC 的**真实 outbound 方向**，或由等价的方向协商保证双方不会出现同时只拨号/只监听；不得固定以邀请码创建/加入角色决定。
- 单条附属 QUIC 应当支持独立 UDP 源端口优先、已验证主 UDP 路径回退、每次重新证书/会话认证、断链及时更新状态、后台退避恢复。SDK 不指定建几条、不创建文件 stream/分片/ACK。
- Control 确实终止时结束当前逻辑会话，报告故障，附属连接不假装恢复；与 Go v0.16.4 一致。跨 Wi-Fi 无缝 ICE Restart 非对等阻塞项。

## 四、状态诊断与关闭（D2、D4、D7、D9）

- SDK 应提供：可用候选与真实提名地址、地址族、各候选的验证/拒绝原因、哪一端实际拨号、STUN NAT 映射类别、网关映射协议/租约、控制/附属连接健康、最近错误、重连次数。诊断信息要脱敏，不输出会话私钥、PIN 之外的敏感凭据、完整 INVITE/REPLY。
- WAN 映射变化后，应准确报告映射失效与链路状态，必要时尝试可验证的重新建连；两端当前都没有成熟的原 Control 会话无缝重建机制，**不将 ICE Restart 冒充 Go 现有功能**。
- 创建、认证失败、竞速失败、网关协议竞争退出、自然关闭、主动取消及 panic/取消任务时要清理 UDP/QUIC、Punch workers、路由器租约。必须具有 fault injection / race tests，避免僵尸映射、端口占用和未完成任务。

## 五、强制验收（D11、D12）

- 比较 Go v0.16.4 和 Rust 在同样网络下：同 LAN、不同 LAN 但相同私网 IP、双公网 IPv6、单侧 IPv6 防火墙、IPv4 对称/多层 NAT、CGNAT、UDP 阻断、PCP/NAT-PMP/UPnP 支持/不支持/失效、网卡重排。
- 记录：成功/失败、实际可达路径、双方拨号方向、建立时间、fallback 次数、认证结果、Control/Data 故障、关闭后的 UDP/映射清理、长时间空闲和数据运行。
- CI 通过只能表示已有自动化通过，**没有真实场景验证不能宣布 Go 全功能完全对等**。

## 六、范围排除

- 不要求 Go/Rust 二进制/邀请码互通。
- 不在 SDK 中实现固定四路 Data lane、文件调度、ACK、重传、传输 UI。
- 不为了代码/依赖数量上的漂亮数字牺牲 mTLS、安全 nonce/replay 防护、NAT 回退和整体穿透成功率。

状态记录以代码 PR、最新 commit 与实际 CI 结果为准，不能混用历史“基础已实现/部分完成”描述。
